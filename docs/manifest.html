Спецификация манифеста (manifest.json)

Файл manifest.json является дескриптором пакетного расширения (папка или .exd). Он информирует клиент о свойствах, авторе, точке входа и запрашиваемых системных правах безопасности.

Однофайловые плагины (.plugin): Если вы создаёте однофайловый плагин (.plugin), создавать manifest.json не нужно — все те же поля объявляются константами прямо в шапке скрипта (__id__, __name__, __version__, __author__, __description__, __permissions__).

Полный пример манифеста

{
  "id": "ox_translator",
  "name": "oxTranslator Pro",
  "version": "1.2.0",
  "author": "@oxDesktop",
  "description": "Автоматический мгновенный перевод сообщений в чатах и каналах.",
  "main": "main.py",
  "icon": "icon.png",
  "min_version": "7.4.3",
  "permissions": [
    "ui",
    "messages.read",
    "messages.send",
    "network"
  ]
}

Таблица полей манифеста

Поле Тип Обязательное Описание
id string Да Уникальный строковый идентификатор. Допустимы буквы, цифры, дефис и подчеркивание (2-32 символа).
name string Да Человекочитаемое название плагина для отображения в настройках клиента.
version string Да Версия плагина в формате SemVer (например, 1.0.0).
author string Нет Никнейм или контакты создателя.
description string Нет Краткое описание возможностей расширения.
main string Да Имя главного исполняемого Python-файла (обычно main.py).
icon string Нет Относительный путь к иконке плагина (PNG/SVG, рекомендован размер 64x64).
permissions array Да Массив ключей доступа, требуемых плагину для работы.

Система разрешений (Permissions)

Для обеспечения приватности пользователей доступ к подсистемам клиента строго разграничен:

  • ui — отображение Toast-уведомлений, баннеров и добавление кнопок в настройки.
  • messages.read — перехват и чтение входящих сообщений в чатах.
  • messages.send — перехват исходящих сообщений, отправка автоматических ответов и модификация текста.
  • network — выполнение внешних HTTP-запросов через модуль urllib или `requests`.
  • files — чтение и запись локальных файлов во внутреннее хранилище плагина.
  • hooks — подписка на системные события жизненного цикла клиента.
